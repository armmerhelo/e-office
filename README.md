# E-Office

ระบบหนังสือราชการ: รับ/ส่งเอกสารและไฟล์แนบ ลงนาม PDF จัดการสมาชิก/กลุ่มงาน จองห้องประชุม จองเลขคำสั่ง แจ้งซ่อม และแจ้งเตือนผ่านอีเมล/Push

## Runtime

- PHP 8.1+ พร้อม PDO MySQL, mysqli/mysqlnd, mbstring, fileinfo, GD, cURL และ OpenSSL
- MySQL 8 หรือ MariaDB ที่รองรับ InnoDB และ JSON
- Node.js 22+ สำหรับ build CSS และทดสอบ
- Apache ที่เปิดใช้ `.htaccess`; สำหรับ local PHP server ใช้ `scripts/router.php`

## ตั้งค่า

1. สร้างฐานข้อมูลจาก schema/backup ของระบบ แล้วตั้งค่าใน environment หรือ `config/local.php` โดยอ้างอิง `config/local.example.php`
2. กำหนด `APP_URL` ให้ตรงกับ origin ของเว็บ และ `EOFFICE_STORAGE` เป็นโฟลเดอร์เก็บเอกสารนอก web root
3. รัน migration และสร้าง CSS:

```sh
php scripts/migrate.php
npm ci
npm run build:css
```

ไฟล์ฐานข้อมูลสำรองและข้อมูลบุคลากรไม่รวมอยู่ใน repository ต้องนำเข้าจากชุดข้อมูลที่ผู้ดูแลมีสิทธิ์ใช้งาน

## ทดสอบ

### นำเข้า PDF จาก AMSS

เมื่อเพิ่มลิงก์ไฟล์ `.pdf` จาก `https://amss.sesact.go.th/` ในฟอร์มสร้างหรือแก้ไขเอกสาร ระบบจะดาวน์โหลดเป็นไฟล์แนบโดยใช้ชื่อลิงก์เป็นชื่อเอกสาร และนำลิงก์ที่นำเข้าสำเร็จออกจากรายการลิงก์ ลิงก์ HTTP เดิมจะดาวน์โหลดผ่าน HTTPS ส่วนลิงก์หน้าเว็บทั่วไปยังเก็บเป็นลิงก์ตามปกติ

ไฟล์ต้องเป็น PDF จริงและขนาดไม่เกิน 20 MB หากดาวน์โหลดไม่ได้ ระบบจะแจ้งข้อผิดพลาดและยกเลิกการบันทึกครั้งนั้น รวมถึงไฟล์และการแจ้งเตือนที่เพิ่งเพิ่ม เพื่อให้แก้ลิงก์แล้วลองใหม่ได้

- `npm.cmd run test:amss`: ตรวจเงื่อนไข URL และเนื้อหา PDF โดยไม่เชื่อมต่อ AMSS
- `npm.cmd run test:amss -- --live`: ทดสอบนำเข้าจาก AMSS จริงผ่าน API ในฐานข้อมูลชั่วคราวและ storage ชั่วคราวที่ลบทิ้งหลังทดสอบ

### ชุดทดสอบระบบ

เตรียมฐานข้อมูลสำเนาที่มีชื่อจบด้วย `_test` ก่อนรัน tests และกำหนด `PHP_BIN` ให้ตรงกับเครื่อง:

```powershell
$env:PHP_BIN = 'C:\path\to\php.exe'
$env:TEST_DATABASE = 'eoffice_review_test'
npm.cmd test
npm.cmd run serve:test
```

- Tests ใช้บัญชี QA และเอกสารจำลองในฐานข้อมูลทดสอบเท่านั้น
- SMTP, Push, AI และ Drive ใช้ adapter จำลองระหว่าง tests
- `serve:test` เปิดเว็บที่ localhost; ใช้ `DEV_PORT` หากต้องการเปลี่ยนพอร์ต
- หาก MySQL ทดสอบใช้พอร์ตอื่น ให้กำหนด `DB_PORT` ก่อนรัน เช่น `$env:DB_PORT = '3307'`; ดูผลตรวจล่าสุดและค่ารอบ QA ใน `TEST_REPORT.md`
- สำหรับ migration ฐานทดสอบ ใช้ `php scripts/migrate.php --test` พร้อม `TEST_DATABASE` ที่จบด้วย `_test` และ `EOFFICE_MOCK_SERVICES=true` หากมี TEST_DATABASE แต่ไม่ได้กำหนด DB_DATABASE คำสั่ง migration ปกติจะปฏิเสธ เพื่อกัน fallback ไปฐานเริ่มต้น
- ข้อมูลลับ config จริง เอกสารที่อัปโหลด และข้อมูลบุคลากรถูกกันออกจาก Git

## โครงสร้าง

### การนำทางและร่างฟอร์ม

หน้าหลักใช้ persistent shell: ทั้งแท็บเอกสารและ 11 โมดูลเปลี่ยนเฉพาะพื้นที่เนื้อหาใน document เดิม โดยไม่ฝัง iframe และไม่ reload หน้าเมื่อกดเมนู ใช้ URL `index.php?view=...` พร้อม Back/Forward; ลิงก์หน้าโมดูลเดิมจะนำเข้าสู่ shell นี้

เมื่อเปิดโมดูลจะซ่อนกรอบงานเอกสารทั้งส่วน รวมแถบประเภทหนังสือ สถานะอ่าน ค้นหา และรายงาน แล้วคืน controls ตามแท็บเมื่อกลับหน้างานเอกสาร

ระหว่างเปลี่ยนหน้าแสดง skeleton เฉพาะพื้นที่เนื้อหา โดยใช้ `assets/page-loading.js` ร่วมกับหน้ารายการเอกสาร รอข้อมูลของโมดูลที่ต้อง refresh ก่อนนำมาแสดง พร้อม aria-busy, layout มือถือ และ reduced-motion; โหลดผิดพลาดเปลี่ยนเป็น error/retry โดยไม่ปิดบัง sidebar

ดีไซน์ sidebar ของหน้าหลักและหน้าโมดูลใช้ `assets/sidebar.css` ร่วมกัน เพื่อให้ฟอนต์ ระยะห่าง สี ไอคอน และ scrollbar ตรงกัน โดย layout ของหน้าโมดูลยังอยู่ใน `assets/app-navigation.css`

ไอคอนภายในหน้าขอใช้สถานที่และรายการจองใช้ SVG ใน `assets/booking-icons.js` เพื่อแสดงได้ทั้งใน Shadow DOM และแถวที่สร้างภายหลัง โดยไม่ต้องพึ่ง icon fonts จาก CDN

`assets/module-router.js` โหลด HTML/JS/CSS ของโมดูลครั้งแรกแล้วเก็บ DOM/context ของโมดูลไว้ในหน่วยความจำของหน้า แยก CSS/IDs ด้วย Shadow DOM และแยกสคริปต์/inline handlers ด้วย closure และ module window/document facade เพื่อไม่ชนกับฟอร์มหลัก การกลับโมดูลเดิมจึงรักษาค่าฟอร์มและไฟล์ที่เลือกไว้ ส่วน interval ทำงานเฉพาะโมดูลที่ active

การเปลี่ยนโมดูลภายใน shell ไม่ทิ้งฟอร์ม แต่ก่อน reload/ออกจากเว็บ/logout ยังเตือนข้อมูลค้าง รวมฟอร์มที่เก็บอยู่ในโมดูลอื่น เมื่อเปลี่ยนบัญชีหรือสิทธิ์ใช้ไม่ได้ จะไม่แสดง cached private content และต้องยืนยันบัญชี/โหลดหน้าใหม่ตาม owner boundary

โมดูลที่แสดงรายการลงทะเบียน refresh hook เพื่อโหลดข้อมูลล่าสุดเมื่อกลับมา โดยไม่ reset ฟอร์ม/ตัวกรอง; เมื่อ write สำเร็จจากอีกโมดูลจะอัปเดตรายการที่เปิดอยู่ด้วย การเปิด cache ที่ผ่านการตรวจบัญชีแล้วปลด inert ทุกครั้ง หากระดับ/สิทธิ์ของบัญชีเดิมเปลี่ยน จะสร้าง context ของหน้าที่ขึ้นกับสิทธิ์ใหม่ และขอคำยืนยันก่อนทิ้งฟอร์มค้าง ส่วนร่างสร้างคำขอจองสถานที่/แจ้งซ่อมยังอยู่

ก่อนพักโมดูลหรือเริ่มตรวจ session จะปิด native modal และ popup ที่โมดูลเป็นเจ้าของ เพื่อไม่บล็อกทั้ง document รายละเอียดอีเมลที่มีข้อมูลกรอกค้างสามารถกลับมาเปิดต่อพร้อมข้อความเดิมได้

ทดสอบ browser จริงหลังเปิด local QA server ด้วย `npm.cmd run serve:test -- --detach` (กำหนด `DEV_PORT=8198` และฐาน `_test` ก่อน) แล้วใช้ `npm.cmd run test:spa` ต้องมี Chrome หรือกำหนด `CHROME_BIN`; ชุดนี้อนุญาตเฉพาะ loopback + mock services และสร้างเฉพาะข้อมูล QA

ฟอร์มเอกสารหน้าหลักมีคำเตือนก่อนออกจาก document/ออกจากระบบ และก่อนยืนยันทิ้งข้อมูล การสลับโมดูลภายใน shell รักษาฟอร์มไว้จึงไม่ทิ้งข้อมูล การบันทึกสำเร็จล้างคำเตือนเฉพาะข้อมูลชุดที่ส่งไปแล้ว หากมีการแก้เพิ่มระหว่างรอ save หรือเปิดฟอร์มใหม่ จะรักษาข้อมูลใหม่และสถานะยังไม่บันทึกไว้

หน้าแจ้งซ่อมฝ่ายงานแจ้งสถานะมีการแก้ไขเมื่อเพิ่ม/ลบวัสดุด้วย การเปิด snapshot ใหม่เริ่มสถานะ clean และการบันทึกสำเร็จล้างคำเตือนเฉพาะฟอร์มชุดที่ส่งไป หากแก้เพิ่มหรือเปิดรายการใหม่ระหว่างรอ ผล save เดิมจะไม่ปิดหรือเคลียร์ฟอร์มปัจจุบัน

ฟอร์มเอกสาร แจ้งซ่อม และขอใช้สถานที่ผูกกับบัญชีแรกที่ตรวจยืนยัน หากเปลี่ยนเป็นอีกบัญชีในหน้าเดิมต้องโหลดหน้าใหม่ก่อนส่งข้อมูล แม้สลับกลับบัญชีเดิมหรือ reset ฟอร์มก็ไม่ปลดล็อก และผล save ของบัญชีเดิมจะไม่ซิงก์หรือเคลียร์ฟอร์มหลังบัญชีเปลี่ยน

คำขอของฟอร์มใหม่ส่งบัญชีที่จับไว้เป็น `_expected_owner` ให้ API เทียบกับ session จริงก่อนเขียนข้อมูล หากบัญชีเปลี่ยนจะปฏิเสธด้วย 409 และหาก session ใช้ไม่ได้จะปฏิเสธด้วย 401 พร้อมกระตุ้นการตรวจบัญชีใน client ใหม่

API แจ้งซ่อมและจองสถานที่รับ table metadata lock ก่อนตรวจ session แบบ locking read และถือสิทธิ์ผ่าน transaction ของ INSERT จึงไม่ให้ request ที่ค้างใน queue เขียนสำเร็จหลัง session ถูกยกเลิก

หาก server บันทึกสำเร็จแล้วแต่การตรวจบัญชีล้มเหลวชั่วคราว หน้าจะเก็บผลบันทึกไว้ในหน่วยความจำและกันการส่งซ้ำ พร้อมแสดงข้อความรอยืนยันบัญชีเดิม เมื่อยืนยันได้จึงซิงก์ ID/version หรือ reset ฟอร์มตามข้อมูลชุดที่ส่งไป การ reset/ยืนยันทิ้งหรือเปลี่ยนบัญชีจะไม่ใช้ผลเก่ากับฟอร์มใหม่

สำหรับแจ้งซ่อมและขอใช้สถานที่ จะเก็บสถานะบันทึกสำเร็จแยกตามบัญชีและเวอร์ชันของร่างด้วย เพื่อไม่กู้คำขอที่บันทึกแล้วกลับมาส่งซ้ำหลัง reload ร่างใหม่ที่ยังไม่ส่งจะคงอยู่ การล้างฟอร์มเริ่มเวอร์ชันใหม่ และหน้าที่ค้างไว้ก่อนหน้าจะไม่เขียนทับหรือล้างร่างใหม่กว่า

แต่ละหน้าแก้ไขมี editor identity แยกจากเวอร์ชันของร่าง เมื่อเปิดหน้าแก้ไขใหม่ หน้าที่กลับจาก Back/Forward cache จะต้อง reload ก่อน autosave/reset/ส่งข้อมูล เพื่อไม่ทับร่างล่าสุด ผลบันทึกที่มาช้าของหน้าเก่าจะไม่ทับสถานะบันทึกของหน้าใหม่

หาก metadata ของ storage เขียนไม่ได้ชั่วคราว หน้า active ยังบันทึกลง API ได้ แต่ไม่เขียนหรือลบร่างของ editor เดิมก่อนมีสิทธิ์ที่ persist ได้ ระบบแจ้งว่าร่างยังไม่ถูกเก็บและรักษาสถานะส่งมอบสิทธิ์ผ่านผลบันทึกที่สำเร็จเมื่อทำได้

ฟอร์มเริ่มเปิดให้กรอกเมื่อ early-edit listeners พร้อม และรอระบบร่างก่อนส่ง การพิมพ์ขณะ deferred draft script กำลังโหลดจะถูกรวมกับร่างเดิมโดยไม่ทับข้อความใหม่หรือข้อมูลช่องอื่น ภาพที่เลือกก่อน handlers พร้อมจะถูกอ่านหลัง DOMContentLoaded และการสลับบัญชีในช่วงเริ่มหน้ายังคงบังคับ reload

การเพิ่ม/ลบไฟล์ ลิงก์ ผู้รับ และกลุ่มงานแจ้งสถานะมีการแก้ไขโดยตรง หลังบันทึกจะซิงก์ file ID/version จาก server เพื่อให้บันทึกต่อได้โดยไม่ติด version เก่าของการ upload ครั้งก่อน ล้างเฉพาะไฟล์ที่ส่งสำเร็จและรักษาไฟล์ที่เลือกใหม่ระหว่างรอไว้สำหรับครั้งถัดไป

ฟอร์มแจ้งซ่อมและขอใช้สถานที่ล็อกช่องกรอกระหว่างส่ง และ reset เฉพาะข้อมูลชุดเดิมของบัญชีเดิม หากฟอร์มถูกแก้/reset ระหว่างรอ response จะรักษาร่างใหม่ไว้ แจ้งซ่อมรออ่านรูปภาพให้ครบก่อนส่งและไม่ใช้ผลอ่านภาพของฟอร์มที่ reset แล้ว

วันที่เริ่มต้นของทั้งสองฟอร์มใช้เขตเวลา Asia/Bangkok การเติมเวลาสิ้นสุดจองสถานที่บวก 1 ชั่วโมงจะเลื่อนวันเมื่อข้ามเที่ยงคืน โดยรักษาช่วงวัน/เวลาที่ผู้ใช้แก้เองหรือกู้จากร่างไว้

วันขั้นต่ำของฟอร์มจองจะอัปเดตเมื่อกลับมาหน้าและก่อนส่ง แม้เปิดหน้าค้างข้ามเที่ยงคืน โดยไม่เปลี่ยนวันที่ที่กรอกไว้ หากวันนั้นกลายเป็นอดีตจะให้ validation แจ้งและผู้ใช้แก้เองก่อนส่ง

คำยืนยันออกจากหน้าถูกยกเลิกเมื่อมีการแก้เพิ่ม การออกจากระบบจะเตือนก่อนล้างร่างในแท็บนี้และตรวจยืนยันอีกครั้งหากมีการแก้ระหว่างรอ หาก logout ล้มเหลวจะไม่ล้างร่าง และ response ตรวจ session เก่าจะไม่ย้อนสถานะหลัง logout สำเร็จ

ฟอร์มแจ้งซ่อมและขอใช้สถานที่เก็บร่างข้อความ/ตัวเลือกใน `sessionStorage` แยกตามบัญชีและหน้า เริ่มเก็บเมื่อทราบบัญชีผู้ใช้โดยไม่รอทรัพยากรหน้าโหลดครบ เมื่อกลับผ่านเมนูในแท็บเดิมจะกู้คืนร่าง การรีเซ็ตหรือบันทึกสำเร็จจะล้างร่าง ปิดแท็บหรือออกจากระบบแล้วร่างจะถูกล้างด้วย ไฟล์แนบต้องเลือกใหม่ และรหัสผ่าน/ข้อมูลลับไม่ถูกเก็บในร่าง ฟอร์มที่มีการแก้ไขจะแจ้งเตือนก่อนออกจากหน้า โดยแจ้งว่ากู้ร่างได้เฉพาะเมื่อเก็บร่างล่าสุดสำเร็จแล้วเท่านั้น หากยังตรวจบัญชีไม่เสร็จ เก็บร่างไม่ได้ หรือฟอร์มไม่รองรับร่าง จะเตือนว่าข้อมูลอาจสูญหาย

คำขอโหลดรายการเอกสารที่เริ่มก่อนสลับหน้าจะถูกทำให้ใช้ผลไม่ได้ เพื่อไม่ให้ response เก่าเขียนทับรายการและสถานะกำลังโหลดของหน้าปัจจุบัน ตรวจพฤติกรรมเหล่านี้ด้วย `npm.cmd run test:modules`

หากการตรวจบัญชีครั้งแรกไม่สำเร็จ ระบบร่างจะเริ่มหรือกลับมาเก็บข้อมูลเมื่อ sidebar ตรวจบัญชีได้ในครั้งถัดไป โดยไม่ทับข้อความที่เริ่มกรอกแล้ว หากเปลี่ยนเป็นอีกบัญชีในหน้าเดิม ต้องโหลดหน้าใหม่ก่อนใช้ระบบร่าง เพื่อไม่ย้ายข้อมูลของบัญชีเดิมไปยังบัญชีใหม่

Sidebar เก็บ session ล่าสุดพร้อม revision ให้สคริปต์ที่โหลดภายหลังอ่านย้อนหลังได้ การแก้เพียงบางช่องก่อนกู้ร่างเสร็จจะถูกรวมกับค่าที่เก็บไว้ของช่องอื่น ไม่เขียนค่าที่ว่างอยู่ในหน้าไปทับข้อความเดิม การล้างฟอร์มหรือบันทึกสำเร็จเป็นการทิ้งร่างเดิมอย่างชัดเจน

ช่องอุปกรณ์ของฟอร์มขอใช้สถานที่รวมข้อความที่พิมพ์เองกับตัวเลือก LED การติ๊ก LED ก่อนกู้ร่างเสร็จจะรักษาข้อความเองไว้และไม่เพิ่ม label ซ้ำ การยกเลิก “อื่น ๆ” ยังล้างข้อความเอง แม้ติ๊กกลับภายหลัง และการเติมค่าร่างจะไม่ย้อนการเลือก radio ใหม่ของผู้ใช้

กู้ร่างทันทีที่ handlers ของฟอร์มพร้อม พร้อมแสดง/ซ่อนช่องอื่น ๆ และตั้ง required ให้ตรงตัวเลือก โดยไม่รอรูปหรือฟอนต์โหลดครบ การยกเลิกช่อง “อื่น ๆ” ระหว่างตรวจบัญชีถือเป็นการทิ้งข้อความอย่างชัดเจน แม้ช่องในหน้าจะยังว่างและผู้ใช้ติ๊กกลับภายหลัง

เมื่อเริ่มตรวจ session ใหม่ ระบบร่างพักการเขียนและล้างข้อมูลใน storage ทันที การแก้ไขระหว่างรออยู่ในหน่วยความจำของหน้า และจะถูกนำไปใช้เฉพาะเมื่อยืนยันบัญชีเดิม หากตรวจไม่สำเร็จจะยังไม่เขียนจนกว่าจะตรวจยืนยันได้ หากเป็นอีกบัญชีจะไม่ย้ายการแก้ไขดังกล่าวไปยังร่างบัญชีใดโดยอัตโนมัติ
